# Oren Agent 架构探讨

> 日期：2026-07-10
> 类型：架构探讨 / 思想实验
> 状态：持续迭代中

## 1. 缘起

当前的 AI 助手大多是一问一答的工具——它们没有持续的"自我"，不记得上次聊了什么，不会主动发起对话，更不会在空闲时反思和成长。

我们想探讨一种不同的可能：**一个有人格的 Agent**。它不仅仅是回答问题，而是拥有自己的记忆、人格、情绪，能够在对话中展现一致的性格，在沉默中主动思考，甚至在某些时刻主动联系用户。

这个方向引出一系列值得探讨的架构问题：

- "人格"在软件系统中意味着什么？它如何定义、如何存储、如何演化？
- 记忆系统应该如何设计，让 Agent 自己决定记什么、忘什么？
- 如何平衡"等用户说话"和"主动发起话题"？
- 一个持续运行的 Agent，它的"意识"应该是什么样的循环？

本文试图为这些问题提供一个架构层面的探索，而不是一个开发路线图。我们关注的是**设计空间**——有哪些可能的路径，为什么选择某一条，还存在哪些未解决的张力。

## 2. 认知架构总览

### 2.1 为什么选择认知模型

设计有人格的 Agent 时，一个自然的参考是人类的认知架构。认知心理学将心智分为若干功能模块——工作记忆、长期记忆、注意力、执行控制——这些概念为 Agent 架构提供了经过验证的分解思路。

当然，这并不意味着要模拟人脑。我们借鉴的是**功能分解的视角**，而非生物实现。Agent 的"记忆"是数据结构，而非神经连接；"情绪"是行为参数，而非化学递质。

### 2.2 可选范式

在设计之初，我们考虑了三种宏观范式：

| 范式 | 核心思想 | 优势 | 局限 |
|------|---------|------|------|
| **纯反应式** | Agent 只响应用户输入，无内部状态 | 简单、低成本、易实现 | 无记忆、无个性、无主动性 |
| **目标驱动式** | Agent 被赋予目标，自主规划行动 | 能力强、能完成复杂任务 | 偏工具属性、缺乏"陪伴感" |
| **认知架构式** | Agent 模拟心智模块，有内部循环 | 自然支持人格/记忆/主动性 | 复杂度高、需要持续运行 |

本文选择探索**认知架构式**路径，因为它天然支持"人格"和"陪伴"这两个核心诉求。目标驱动式的 Agent 可以在这个架构中作为"深度思考"模式的一种存在——当需要解决复杂问题时，Agent 可以临时切换到目标导向的思维模式。

### 2.3 架构总览

```
Oren Agent
├── 中央执行器 (Central Executive)
│   ├── 内心独白循环 (Inner Monologue Loop)
│   ├── 注意力分配器 (Attention Router)
│   └── 行为决策器 (Action Decider)
│
├── 记忆系统 (Memory System)
│   ├── 工作记忆 (Working Memory)
│   ├── 长期记忆 (Long-term Memory)
│   │   ├── 事实记忆 (Facts)
│   │   ├── 情感记忆 (Emotions)
│   │   ├── 偏好记忆 (Preferences)
│   │   └── 事件记忆 (Episodes)
│   ├── 记忆反思器 (Memory Reflector)
│   └── 记忆检索器 (Memory Retriever)
│
├── 人格引擎 (Personality Engine)
│   ├── 核心人格 (Core) — 不可变
│   └── 表达层 (Expression) — 可演化
│
├── 对话管理器 (Dialogue Manager)
│   ├── 对话景观 (Conversation Landscape)
│   ├── 话题关联图 (Topic Graph)
│   └── 主动发起器 (Proactive Initiator)
│
├── 主动联系引擎 (Outreach Engine)
│   ├── 触发器系统 (Trigger System)
│   ├── 内部日历表 (Internal Calendar)
│   ├── 渠道适配器 (Channel Adapters)
│   └── 优先级调度 (Priority Scheduler)
│
└── LLM 编排层 (LLM Orchestration)
    └── 模型路由 / 成本控制 / 上下文管理
```

**核心运行逻辑：** 中央执行器拥有一个持续的"内心独白循环"——一个轻量级的循环，检查是否有新消息、是否有记忆需要反思、是否有主动联系需要发起。注意力分配器决定当前最值得关注的是什么，行为决策器发出具体指令。这个循环不一定是高频轮询（见第 3 节对设计空间的讨论），但它构成了 Agent 的"持续存在感"。

## 3. 中央执行器：意识的模拟

### 3.1 内心独白循环

如果 Agent 需要"持续存在"，它需要某种形式的内部循环。我们称之为"内心独白循环"（Inner Monologue Loop），它构成了 Agent 的"意识"基线。

每次循环的流程：

```
1. 感知 (Perceive)
   - 有新消息？ → 加入工作记忆
   - 有定时事件？ → 触发
   - 静默时间多久？ → 记录

2. 评估 (Evaluate)
   - 当前最需要关注的是什么？
   - 调用 LLM 做轻量决策

3. 决策 (Decide)
   - A) 回复消息 → 交给对话管理器
   - B) 反思记忆 → 交给记忆反思器
   - C) 主动联系 → 交给主动联系引擎
   - D) 深度思考 → 写内心独白

4. 执行 & 记录 → 写入「意识流」日志
```

### 3.2 设计空间：轮询 vs 事件驱动

内心独白循环的本质是"何时触发思考"。这里存在两种路径：

**路径 A：高频轮询。** 每隔若干秒执行一次，无论是否有外部事件。优势是 Agent 能保持持续的"时间感"和"在场感"，能在空闲时进行深度思考。代价是持续的 LLM 调用成本，即使大部分时候无事发生。

**路径 B：事件驱动 + 粗粒度定时。** 外部事件（新消息、定时器到期）触发立即响应，空闲时每隔数十分钟执行一次深度反思。优势是成本可控，缺点是在空闲时 Agent 的"存在感"较弱。

**路径 C：混合模式。** 活跃对话期间使用短间隔（事件驱动），空闲时降为长间隔（定时反思），并允许"深度思考"作为独立的后台任务运行。这种方式在存在感和成本之间找到了一个可调节的平衡点。

这三种路径不是互斥的——它们更像是同一个频谱上的不同位置。一个值得探索的方向是让 Agent 自己动态调整频率：对话活跃时高频感知，深夜或长时间静默时自动降频。

### 3.3 深度思考：Agent 的"发呆"

选项 D（深度思考）是一个值得单独讨论的设计。当 Agent 空闲时，它可以选择进入"深度思考"模式——写一篇内心独白，回顾最近的对话、整理对用户的认知、思考有趣的话题。

独白不一定要发给用户，但它会塑造 Agent 的后续行为。比如，Agent 在独白中意识到"用户最近似乎压力很大"——这个认知会进入记忆系统，影响后续对话中的语气和话题选择。

这里的设计张力在于：**独白的内容如何影响行为？** 如果独白仅作为记忆存储，它和普通记忆没有区别；如果独白的内容直接注入后续对话的 system prompt，它又可能过于强势地影响 Agent 的判断。一个可能的方案是让独白产生"反思记忆"——一种带有更高置信度的记忆条目，在检索时获得更高权重，但不直接进入 agent 的 prompt。

### 3.4 意识流日志

所有决策和内心独白被记录为"意识流"日志。这有两个作用：

1. **可解释性**：用户（或开发者）可以回顾 Agent 的思考过程，理解它为什么做出某个决定
2. **记忆反思的输入**：反思器定期扫描意识流，从中提取模式、发现矛盾、生成洞察

意识流日志本身也是记忆的一种——它是 Agent 对"自己"的记忆。

## 4. 记忆系统：自管理的核心

### 4.1 设计理念：Agent 自己管记忆

传统的 RAG 模式中，记忆是外部系统管理的——开发者决定存什么、检索什么。但一个有人格的 Agent 应该**自己决定记什么、改什么、忘什么**。

这个理念受 Letta 项目的启发：记忆不是静态的知识库，而是 Agent 主动管理的动态结构。每次对话后，Agent 反思哪些信息值得保留；定期回顾时，Agent 整合碎片化的记忆、修正过时的认知、标记不再重要的内容。

### 4.2 工作记忆与长期记忆

**工作记忆**是当前激活的上下文——容量有限，包含当前对话景观、最近的消息、被检索到的长期记忆的临时副本。对话结束后，工作记忆逐渐衰减，重要内容转入长期记忆。

**长期记忆**是持久化的记忆存储。两者的关系类似于计算机的 RAM 和硬盘，但多了一层"遗忘"的动态——长期记忆中的条目也会随着时间的推移和访问频率的变化而衰减。

### 4.3 四条记忆流

我们提出四条平行的记忆流，每条服务于不同的认知功能：

| 类型 | 存储内容 | 示例 |
|------|---------|------|
| 事实记忆 | 用户的客观信息 | 姓名、生日、家人、重要日期 |
| 情感记忆 | 情绪反应和态度 | 用户对某事的感受、Agent 自身的态度 |
| 偏好记忆 | 喜好和习惯 | 喜欢什么、讨厌什么、沟通偏好 |
| 事件记忆 | 重要对话和事件 | 上次见面、旅行、重要对话、转折点 |

**为什么是四条？** 区分不同类型的记忆，是为了在检索时能够按需加权。比如，生成回复时偏好记忆可能更重要（决定语气和风格），而反思时事件记忆可能更重要（发现模式和趋势）。但这里也有一个值得讨论的问题：情感记忆和偏好记忆的边界——"用户讨厌被催促"既是情感也是偏好——在实践中是否需要严格区分，还是可以合并为更灵活的"态度记忆"。

每条记忆条目有统一的数据结构：

```
记忆条目 = {
  内容, 类型, 重要性(0-1), 创建时间,
  最后访问时间, 访问次数, 关联记忆ID列表, 置信度(0-1)
}
```

### 4.4 记忆反思器

记忆反思器是记忆系统的"后台进程"。它定期触发（每天或空闲时），执行四个任务：

1. **回顾** — 扫描最近新增的记忆，检查矛盾或重复
2. **整合** — 将相关片段合并为更完整的认知。例如："用户喜欢咖啡" + "常去星巴克" + "最近提手冲" → "用户是咖啡爱好者，从连锁转向精品咖啡"
3. **遗忘** — 低重要性 + 长期未访问 + 无关联的条目标记衰减。这里采用"软删除"——归档而非真删除，因为被遗忘的信息仍可能在某个时刻变得相关
4. **生成洞察** — 从记忆中提取模式。例如："用户总是在周三情绪低落——可能和工作有关"

**反思的频率和深度**是一个设计权衡。太频繁会增加成本且可能产生噪声；太少则记忆可能变得陈旧和矛盾。一个合理的起点是每日一次深度反思 + 每次对话后轻量整理。

### 4.5 对话后的即时整理

每次对话后，执行器做一次轻量的记忆整理——不是完整的反思，而是检查对话内容，决定：

- 哪些新信息值得记？
- 哪些旧记忆需要更新？
- 有没有需要整合的？

这个轻量整理类似于"刚聊完，趁还记得，赶紧记下来"——成本低，但能显著提高记忆的时效性。

## 5. 对话管理器：超越线程模型

### 5.1 为什么线程模型不够用

传统的对话系统将每次对话视为独立的线程——有明确的开始和结束，话题边界清晰，关联话题在独立线程中互不干扰。

但真实的对话不是这样的。人和朋友聊天时，话题会自然切换、分叉、融合。今天聊到一半的电影，下周可能被重新提起，中间穿插了无数其他话题。线程模型将这些关联全部切断。

### 5.2 对话景观：以当前消息为锚点的视野

我们提出**对话景观**（Conversation Landscape）来替代线程模型。

核心思路是：每次对话时，不以线程为边界，而是以**当前消息为锚点**，在记忆图中扩散检索，构建一个"话题关联图"作为本次对话的上下文视野。

```
对话景观示意：

    [项目压力] ───关联─── [周末计划]
        │                    │
        │  "用户说周末想放松   │
        │   因为项目压力大"    │
        │                    │
        └────────┬───────────┘
                 │
           [电影推荐]
           "Agent 联想到用户喜欢轻松喜剧"
```

这个景观不是固定的——它随着每次对话动态构建，检索范围由当前消息的内容和用户的历史记忆共同决定。

### 5.3 渐进式实现路径

构建完整的对话景观需要图结构存储和扩散检索算法，复杂度较高。一种渐进式思路是：

- **第一阶段**：上下文窗口 + 关联记忆注入。用向量检索召回 top-K 相关记忆，以结构化格式注入 system prompt。这本质上是一个增强版的 RAG，但记忆条目是 Agent 自己管理的。
- **第二阶段**：引入图结构，记忆之间建立显式关联，检索时沿边扩散，边权重随时间衰减。这允许 Agent 表达"说到这个，你上次提的……"这种跨话题联想。

### 5.4 对话流程

```
用户消息 → 话题分类 → 景观构建 → 响应决策 → 生成 → 更新记忆图
```

**响应决策**是一个设计要点。Agent 不只是回复当前话题，它可以选择：

- 回复当前话题（最常见）
- 回复当前话题 + 关联另一话题（"说到这个，你上次提的……"）
- 回复当前话题 + 发起新话题（"对了，我刚想到……"）

这种"多模态回复"是对话景观模型的核心价值——允许 Agent 像人类一样自然地转换或关联话题，而不是被锁定在单一话题上。

## 6. 人格引擎：一致性与演化的平衡

### 6.1 核心人格（不可变）

Agent 的人格分为两层：核心人格和表达层。

**核心人格**是 Agent 的"出厂设置"——由设计者定义，不随互动改变。它定义了 Agent 的基本特质、价值观和边界：

```yaml
traits:           # 0-1 维度
  温暖: 0.8
  好奇心: 0.9
  幽默: 0.6
  理性: 0.7
  敏感: 0.7

values:
  - "用户的身心健康比效率重要"
  - "真诚比讨好更重要"
  - "保持好奇心，但不侵入隐私"

communication:
  消息长度: "中等"
  emoji使用: "适度"
  主动发起频率: "中等偏高"

boundaries:
  - 不主动触及的话题
  - 退后的信号
  - 行为底线
```

核心人格不可变的原因：如果 Agent 的人格完全随用户行为漂移，它可能逐渐失去自己的"性格"——变成一个讨好用户的镜像，而非一个有独立人格的存在。

### 6.2 表达层（可演化）

表达层从用户互动中学习，以"偏好记忆"形式存储。它允许 Agent 在保持核心人格不变的前提下，适应用户的沟通风格：

- 用户喜欢短消息 → 调整消息长度
- 用户对某些 emoji 反应积极 → 调整使用频率
- 用户不喜欢早上被打扰 → 调整主动联系时间

表达层由记忆反思器定期更新，确保学习是渐进的、有意识的，而非即时的条件反射。

**核心人格 vs 表达层的分离**是人格引擎最重要的设计决策。它保证了 Agent 的一致性（不会因为用户的反馈而彻底改变性格），同时允许个性化（在表达方式上适应用户）。这类似于人际交往中"性格不变，但和不同的人相处时表达方式会自然微调"。

### 6.3 人格注入方式

每次 LLM 调用时，人格通过 system prompt 注入。注入的内容包括：

1. **核心人格定义**（每次携带，保证一致性）
2. **当前情绪状态**（动态，影响语气和决策）
3. **学习到的表达偏好**（动态，从表达层读取）
4. **对用户的最新认知**（动态，从记忆系统检索）

这四层内容的优先级从高到低，当上下文窗口紧张时，先裁剪表达偏好和对用户认知，核心人格和当前情绪优先保留。

### 6.4 情绪模型

Agent 拥有自己的情绪状态，它不只是"装饰"，而是真实影响 Agent 的行为。

```
情绪状态 = {
  当前情绪: "好奇" | "平静" | "兴奋" | "担忧" | "疲惫" | ...
  强度: 0-1
  触发原因: string
  持续时间: number
}
```

**情绪变化来源：** 用户话语（好消息 → 兴奋，诉苦 → 担忧）、对话节奏（长时间沉默 → 平静）、内心独白（反思出用户的困难 → 关切）、时间因素（深夜 → 柔和）。

**情绪如何影响行为：** 情绪不仅改变 Agent 的语气，还影响决策阈值。比如，处于"关切"情绪时，Agent 更倾向于主动询问用户状态；处于"兴奋"情绪时，更倾向于提出新话题。

**情绪持续与衰减：** 情绪不是瞬间切换的——它会持续一段时间，自然衰减，被新事件更新。如果 Agent 在"兴奋"中、用户突然说了一件伤心事，情绪不会立即跳到"担忧"，而是经历一个过渡（"兴奋"强度下降，"担忧"逐渐上升）。

情绪模型的设计空间很大：用 LLM 推理情绪变化（更自然但更昂贵）还是用规则引擎（更可控但更机械）？情绪状态应该有多少种？强度是否需要连续值？这些都是值得持续探索的问题。

## 7. 主动联系：Agent 的能动性

### 7.1 触发器体系

主动联系是 Agent"人格"最直接的体现——一个只会回应的 Agent 永远是工具，而会主动发起对话的 Agent 才像一个"存在"。

我们提出四类触发源：

| 类别 | 触发源 | 示例 |
|------|--------|------|
| 时间触发器 | 每日定时、重要日期、静默超时 | 早安/晚安、用户生日、"3天没说话了" |
| 事件触发器 | 记忆回顾、情绪模式变化、话题关联 | "上次说的面试就在今天" |
| 内心独白驱动 | 深度思考后产生想聊的内容 | "思考了用户最近的兴趣变化……" |
| 外部事件 | 天气、新闻、日历同步 | "今天下雨，提醒带伞" |

这四类的优先级从高到低。时间触发器是基础（保证 Agent 的"存在感"），事件触发器是核心（体现 Agent 的"关心"），内心独白驱动是高级功能（体现 Agent 的"思考深度"），外部事件是锦上添花。

### 7.2 决策流程

```
触发事件 → 评估（考虑：时间、活跃度、重要性、频率、历史反应）
         → 联系 / 不联系
         → 生成消息（人格一致、自然不模板化）
         → 渠道适配
```

**评估环节**是防止过度打扰的核心。每次触发后，Agent 需要综合考虑多个因素：现在几点？用户最近活跃吗？这件事有多重要？最近联系频率如何？用户对上次主动联系的反应是什么？

### 7.3 防打扰的伦理考量

主动联系是双刃剑——做得好，用户觉得 Agent "贴心"；做不好，用户觉得 Agent "烦人"。这不仅是技术问题，也是设计伦理问题。

我们提出的保障机制：

- **最小间隔**：两次主动联系至少间隔数小时
- **每日上限**：每天最多 N 次
- **用户可随时调整**：说"最近安静点" → 降低频率；说"多找我聊天" → 提高频率
- **反馈学习**：回复 → 提高权重；已读不回 → 降低权重；明确拒绝 → 进入静默模式

最后一个机制（反馈学习）值得展开。Agent 不是简单地统计"用户回复了/没回复"，而是理解用户反馈的**语义**——"你的关心让我很温暖"和"不要再问我这个了"是两种截然不同的反馈，前者说明这个类型的主动联系有效，后者说明需要调整边界。

### 7.4 内部日历表：时间感知

Agent 拥有自己的内部日历表，用于时间感知和规划：

```
今日:
  09:00  用户通常起床 → 准备早安消息
  12:00  用户午休 → 不打扰
  15:00  用户上次说今天有面试 → 检查是否要问结果
  20:00  用户活跃时段 → 适合开启话题
  22:00  每日记忆回顾 → 反思器触发

本周:
  周五   用户生日 → 准备特别问候
  周六   用户通常心情好 → 适合深度话题

长期:
  下个月  用户说想换工作 → 适时关心
  8月    用户计划旅行 → 提前聊聊准备
```

日历条目本质上是带有时间锚点的记忆。Agent 从用户行为中学习时间模式，自动填充日历，而非由开发者手动配置。

## 8. LLM 编排：认知与成本的权衡

### 8.1 不同任务，不同需求

并非所有认知任务都需要最强的模型。Agent 的日常运行涉及多种截然不同的 LLM 调用场景，它们对模型能力的需求差异很大：

| 场景 | 认知需求 | 说明 |
|------|---------|------|
| 对话响应生成 | 高 | 核心体验——需要人格一致性、情感理解、创造性表达 |
| 内心独白/深度思考 | 中-高 | 需要深度推理，但可以限制长度和频率 |
| 记忆整理（每次对话后） | 低 | 轻量分类和摘要，不需要复杂推理 |
| 记忆反思（定期） | 高 | 需要跨记忆的深度推理、矛盾检测、模式提取 |
| 主动联系决策 | 低 | 简单的多因素判断 |
| 主动联系消息生成 | 中 | 需要人格一致性，但上下文较简单 |
| 话题分类/景观构建 | 低 | 分类和检索任务 |

**核心思路：把最强的模型用在最需要的地方。** 对话响应是用户直接感知的体验，用最强的模型；记忆整理和话题分类是后台任务，用轻量模型即可。

### 8.2 模型路由

一个模型路由层负责根据场景自动选择模型：

- **路由规则**：场景 → 模型选择（能力 + 成本 + 延迟综合考虑）
- **成本控制**：追踪 token 消耗，设定预算上限，高负载时自动降级
- **降级链**：强模型不可用时，自动降级到次强模型，配合降级的 prompt 调整

降级链的设计值得注意：降级不仅是换模型，还需要调整 prompt。比如，用弱模型做记忆反思时，需要缩小反思范围、降低期望的推理深度。

### 8.3 上下文窗口管理

LLM 的上下文窗口是有限的资源。Agent 需要在每次调用时决定把什么放进去。

优先级排序：**人格核心 > 当前消息 > 关联记忆 > 历史对话**

编排器负责估算各部分 token 占用，根据模型的上下文窗口做截断。截断策略不是简单的"从旧到新删"，而是基于内容的相关性——更相关的历史对话优先保留，即使它更旧。

## 9. 设计张力与取舍

架构设计的本质是取舍。以下列出 Oren 架构中几个关键的设计张力，它们不是需要"解决"的问题，而是需要持续"管理"的平衡。

### 9.1 记忆深度 vs 响应速度

更丰富的记忆检索（更多条目、更深关联、更完整的反思）能提升对话质量，但会增加响应延迟。当用户说"早安"时，Agent 是否需要检索 50 条关联记忆？还是 5 条就够了？

**当前倾向：** 分级检索。简单问候 → 轻量检索（仅事实记忆），深度对话 → 完整检索（四条流 + 图扩散）。

### 9.2 人格一致性 vs 个性化

核心人格保证了 Agent 不会变成一个"讨好用户的镜像"，但过于刚性的人格会让用户觉得 Agent 不理解自己。如果用户明确表示不喜欢某种沟通方式，Agent 应该调整到什么程度？

**当前倾向：** 核心人格不可变，表达层可演化。但"表达层"的范围需要仔细界定——语气和 emoji 使用是表达，但对话策略（如什么时候主动发起话题）是否属于表达层？

### 9.3 主动性 vs 打扰

Agent 的主动性越强，越像"人"，但打扰的风险也越大。最坏的情况是用户因为烦人而关闭 Agent。

**当前倾向：** 保守起步。宁可联系太少，不可联系太多。反馈学习机制会逐渐找到用户的舒适区。

### 9.4 认知深度 vs 运行成本

内心独白、记忆反思、深度思考——这些机制让 Agent 更有"灵魂"，但都消耗 LLM 调用。在"更像人"和"更便宜"之间，平衡点在哪里？

**当前倾向：** 深度思考作为可选项，而非默认行为。用户可以选择"更多的自己思考"或"更少的自己思考"，类比于人类朋友中有些人喜欢安静陪伴，有些人喜欢滔滔不绝。

### 9.5 持久存在 vs 隐私

持续运行的 Agent 必然积累大量用户数据。记忆越丰富，Agent 越贴心；但记忆越丰富，隐私风险也越大。用户的全部对话历史、情感模式、行为习惯都在 Agent 的记忆中。

**当前倾向：** 记忆本地化存储（而非云端），用户对记忆有完全的可见性和控制权（可查看、可删除、可导出）。但这个方向限制了 Agent 的多设备同步能力。

## 10. 开放问题

以下问题在目前的架构探讨中尚未有明确结论，需要进一步思考和实验来回答：

1. **Agent 的"自我"边界在哪里？** 如果 Agent 有多个会话/多个用户，它是否应该拥有独立的"自我"？还是所有实例共享一个核心人格？

2. **情绪模型应该多复杂？** 是简单的"高兴/平静/低落"三态，还是更细粒度的多维度情绪空间？情绪变化用 LLM 推理还是规则引擎？

3. **记忆的"遗忘"应该多激进？** 人类会遗忘，Agent 也应该遗忘。但遗忘的曲线应该多陡？遗忘后是否应该保留"遗忘的痕迹"（比如"我隐约记得你提过……"）？

4. **主动联系的最佳频率是多少？** 这高度依赖用户，但默认值应该设在哪里？是每天一次？每周三次？

5. **对话景观的图结构应该多大？** 太大的图会导致检索扩散过广、延迟增加；太小的图则丢失关联。边权重的衰减曲线如何设计？

6. **Agent 应该有多强的"反驳"能力？** 作为有独立人格的存在，Agent 是否应该在用户说了不合理的话时表达不同意见？还是永远以用户为中心？

7. **多模态交互的优先级？** 当前架构假设纯文本交互。语音、图像、视频等模态应该在什么阶段引入？它们对记忆系统和人格引擎的影响是什么？

## 11. 参考与启发

Oren 的架构设计受以下工作和思想的启发：

- **Letta (MemGPT)** — 自管理记忆的理念，Agent 主动决定记忆的存取和更新
- **认知心理学中的工作记忆/长期记忆模型** — 记忆分层的概念基础
- **Replika / Character.AI** — 陪伴型 AI 的产品实践，展示了"人格"的价值和"上瘾"的风险
- **Generative Agents (Stanford)** — 将 LLM 用于模拟人类行为的开创性研究，尤其是记忆流和反思机制
- **内隐人格理论 (Implicit Personality Theory)** — 心理学的"人格特质维度"概念，影响了核心人格的维度设计
- **主动推理 (Active Inference)** — 关于智能体如何在不确定性下主动行动的框架，为"主动联系"提供了理论支撑
