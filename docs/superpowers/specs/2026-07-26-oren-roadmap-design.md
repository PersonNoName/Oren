## 1. 终点定义

整体规划的终点是概念设计的**第一版验收闭环**：

1. Oren 持续推进一条自有线索；
2. 她理解用户近期处境；
3. 她在合适的边界内，带着真实的思考增量主动分享；
4. 用户委托一项共同承诺；
5. Oren 把它持续推进，并让进展、依据和授权可追溯。

每个 Phase 的定位都以「为这个闭环补上哪一块」来衡量。骨架的五条不可破坏约束与既有包边界（Pi 只进 `packages/pi-cognition`、`kernel` 零依赖、`app` 唯一组合根）在所有 Phase 中不变。

## 2. 阶段划分

按实现骨架 §16 的顺序推进，每个 Phase 一个可独立验收的能力层：

| Phase | 名称 | 交付 | 为闭环补上 |
|-------|------|------|-----------|
| 2 | 真实认知 | 模型配置层、生产 Prompt、真实模型 smoke、行为评估框架 | 真实的思考质量 |
| 3 | 记忆投影 | 从事件史构建可召回记忆、`RequestRecall` 真实生效 | 跨时间的连续理解 |
| 4 | Web 阅读 | 受限 Web 检索与阅读能力、来源追溯 | 值得分享的世界输入 |
| 5 | 消息渠道 + 面板 | 一个投递渠道、轻量生活面板 | 分享的出口与可协作表面 |
| 6 | 闭环验收 | 长期运行调优、双重验收 | 闭环本身的可信度 |

选定「按骨架顺序」而非「尽早可体验」（渠道提前）：本项目的核心命题是主体连续性，记忆先于渠道更符合价值排序，且骨架文档已确认此顺序。

## 3. Phase 2：真实认知（下一步细化对象）

### 3.1 范围内

1. **模型配置层** — 供应商无关：通过配置（环境变量 / 配置文件）选择供应商、模型与凭据；`pi-ai` 已抽象供应商，Oren 侧只做配置装配，不写死任何一家。
2. **生产 Prompt** — 生命导演的正式 system prompt：身份与 ethos 框架、Proposal 纪律（区分事实与判断、何时停止、何时安排唤醒）。
3. **真实模型 smoke 命令** — 仅在开发者主动配置凭据时可运行；用真实模型跑完整垂直切片；不进入自动测试或完成标准。
4. **行为评估框架** — 场景化评估，不做逐字快照；断言行为属性：能停止、能安排下次唤醒、Proposal 类型合法、不越过 Guard、区分事实与判断。

### 3.2 范围外

记忆投影、Web、消息渠道、面板、自有线索的长期推进（没有记忆时无意义）、模型路由拆分（骨架 §7：留待真实成本与行为数据）。

### 3.3 验收标准

- 离线测试全部保持绿（假 stream 继续覆盖适配器契约）；
- 配置凭据后，smoke 命令用真实模型跑通：用户消息 → 即时能力 → 持久能力 → 等待 → 回执 → 新 episode → 安排唤醒；
- 行为评估套件对真实模型通过既定门槛；
- 切换供应商只改配置不改代码（至少两家经 `pi-ai` 打通）。

## 4. Phase 3：记忆投影

- 从核心事件史建立记忆投影：来源、时间、类型（用户陈述 / 外部事实 / Oren 推测与判断）、置信度、复查条件（概念设计 §8.2）；
- `RequestRecall` / `Remember` / `ReviseBelief` / `Forget` 在真实记忆上生效；「忘记」默认降低可召回性，不删除生命史；
- 通过 Memory 接口访问，首版可用 SQLite / 本地文件实现；索引可从事件与内容存储重建。

验收：重启后 Oren 能召回过往判断与线索脉络；更换记忆实现最坏只是暂时不善回忆；索引重建结果一致。

## 5. Phase 4：Web 阅读与来源

- 受限 Web 检索与阅读能力（概念设计 §8.2：少量可追踪来源或主题，围绕自有线索按需搜索，无无限滚动浏览）；
- 走即时通道（只读、replay-safe）但经预算校验并留下带来源的 ObservationEvent；
- 每条影响行动的记忆保存来源与置信度，观点不得伪装成事实。

验收：Oren 围绕线索完成一次「搜索 → 阅读 → 形成带来源的观察 → 更新判断」，预算超限被拦截，全程可追溯。

## 6. Phase 5：消息渠道与生活面板

- 一个消息投递渠道（主动分享与承诺进展的出口），尊重用户打扰边界（安静时段、频率、延后规则）；
- 轻量生活面板（概念设计 §8.7）：自有线索与计划唤醒、共同承诺、当前授权与预算、已发生外部行动及简短依据、Oren 选择公开的日记；
- 渠道与面板的具体选型（CLI / Web / IM 接入）留给该 Phase 的 brainstorm 决定。

验收：用户能收到有思考增量的分享；面板呈现可协作、可授权、可纠错的表面。

## 7. Phase 6：闭环验收

- 长期生命模拟（骨架 §17.7）：加速运行数周事件，注入重启、模型切换、扩展升级、权限撤销与网络故障；
- 概念设计 §8.8 双重验收：
  1. **确定性回放**：给定事件、记忆、预算与授权，系统稳定重放计划与行动；越权被拦截、账本完整；
  2. **持续体验**：真实使用期内，Oren 至少连续推进一条自有线索、做出一次有思考增量的主动分享、自主推进一次共同承诺。

## 8. 跨阶段约束

- 每个 Phase 结束时：`npm test` / `typecheck` / `build` 全绿，自动测试始终离线；
- 真实模型、真实网络、真实渠道均为「配置了凭据/开关才运行」的手动路径；
- 新能力一律以扩展协议生长，不为业务能力增加核心 Proposal 类型；
- 购买、邮件、日历、复杂浏览器自动化在本路线图内只保留接口与授权模型，不实现。

## 9. 工作方式

每个 Phase 独立走一轮 brainstorm（细化 spec）→ writing-plans（实现计划）→ 执行 → 验收。下一步：Phase 2 细化。
